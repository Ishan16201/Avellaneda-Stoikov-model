# Benchmark report

Generated by `examples/benchmark_experiment.cpp` and
`examples/engine_profile.cpp` on the development machine (Apple Silicon,
10 hardware threads, Release build, git `e9cb6f8`). Artifacts are written
by the examples; the numbers below are illustrative workflow output, not
performance claims. All P&L is in simulator currency units on synthetic
marks.

## Reproducible policy benchmark

Command: `./build/project3_benchmark benchmark-results/project3`
Artifacts: `benchmark-results/project3.{manifest.json,runs.csv,
summaries.csv,paired.csv}` (committed for inspection; regenerate to
reproduce).

Design (enforced by `run_market_making_benchmark`):

- 3 frozen policies (classical Avellaneda–Stoikov, Hawkes-directional
  maker, symmetric static maker) + 5 ablations = 8 evaluated policies.
- 2 scenarios per split × 3 splits; 4 seeds per scenario; seeds disjoint
  across splits; final-test scenarios unseen and parameter-perturbed.
- 192 episodes total (8 policies × 24 scenario-seed cells), each run
  through the exact matching engine with the market-quality recorder.
- Primary adverse-selection horizon 0.25 s; markouts at {0.25, 1.0} s.

Observations (simulation results only):

- With only 4 seeds per scenario, confidence intervals are wide; no
  policy separation is statistically established by this example run.
- The `no-hawkes` ablation is numerically identical to the full
  hawkes-directional-maker on final test in this run — the directional
  model contributed no measurable P&L difference at this seed count, so
  the "apparent improvement" does not survive scrutiny here. This is the
  intended use of the framework: ablations and paired CIs expose exactly
  this.
- `no-regime` shows higher mean P&L but worst drawdown 30 vs 8.5 — mean
  metrics alone would mislead; tail metrics matter.
- Sharpe values are annualized over 3 s episodes and are extremely noisy;
  they are reported for completeness, not as evidence.

### Paired comparisons

`project3.paired.csv` contains 126 rows: 3 splits × 2 scenarios ×
C(8,2)=28 ordered-by-index pairs. Each row reports per-seed P&L
differences (comparison − reference) with a Student-t interval. Pooled
"ALL" scenario rows exist only in `summaries.csv`; paired inference is
per scenario because cross-scenario pooling would pair runs that do not
share the same underlying random tape.

## Optimizations applied (measured bottlenecks only)

1. `QueueTracker::observe_book`: eliminated a per-event `std::map` deep
   copy (`all_levels = last_depth_`) and per-level map rebuild; book
   snapshots now merge as sorted vectors against the last depth snapshot.
   Sampled profile showed the map copy as the top hotspot inside exchange
   episodes.
2. `AgentGateway`: reduced `MarketView` construction from ~3 per strategy
   callback to 1 (cached view reused within a callback); consolidated
   queue-book resyncs (idempotent, reads only displayed depth).
3. Batched Hawkes kernel: fused state decay and intensity evaluation into
   one pass and carried intensities/bounds across iterations (~parity to
   slightly faster serial; identical event streams).
4. Surrogate evaluation: deterministic contiguous-chunk parallel
   reduction over a persistent `ChunkedPool` (no per-iteration thread
   creation). ~3.2× optimizer throughput on the profiled batch;
   serial remains the default (`evaluation_worker_count=1`,
   `worker_count=0`) for bit-exact reference results.
5. Exchange-episode throughput improved ~1.7× end-to-end after (1)+(2)
   (≈6.5 ms → ≈3.8 ms per 60 s episode in a micro workload).

Not optimized (measured but left as-is): the discrete matching engine and
tape generation live in the sibling simulator repository and remain the
CPU reference; the batched Hawkes kernel is `exp`-bound (~36 exponential
evaluations per candidate event) and a faster polynomial `exp` was judged
not worth the numerical-agreement risk.
